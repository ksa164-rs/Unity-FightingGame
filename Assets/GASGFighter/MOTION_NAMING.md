# モーション命名・管理ルール

Unity 6000.3.11f1向け。2026-09-07に既存17モーションへ適用しました。

## 普段使う情報は3つ

| 項目 | 例 | 役割 |
|---|---|---|
| 管理番号 | `AS_p01_000_001` | 固定の識別番号。登録後は変更しない |
| 表示名 | `待機` | 内容が分かる名前。日本語で自由に変更できる |
| Animation Clip | `wait.anim` | 再生する実データ。差し替え可能 |

画面では **`AS_p01_000_001 / 待機`** と表示します。番号だけで技の内容を覚える必要はありません。

## 番号の意味

`AS_p01_000_001`

- `AS`：モーションデータ。
- `p01`：キャラクター番号。`p01`〜`p99`。対戦の1P／2Pや色違いとは関係ありません。同キャラ対戦なら両者とも同じ番号を使います。
- `000`：分類番号。
- `001`：分類内の連番。`001`〜`999`。全角文字・空白を使用しません。

| 分類 | 内容 | 登録例 |
|---|---|---|
| `000` | 基本移動 | 待機、しゃがみ待機、ジャンプ、着地、ステップ |
| `100` | 通常攻撃 | 立ち弱P、立ち中P、立ち強P |
| `200` | 必殺技 | 昇龍拳（弱）、波動拳 |
| `300` | 投げ | 前投げ |
| `400` | 防御・被弾 | ガード、被弾、ダウン、投げられ |
| `900` | システム | ラウンドリセット |

分類は今回の管理用に定めたものです。空き番号へ割り当てる場合も、発生F・ダメージ・Clipの版数など変更しやすい情報は番号へ含めません。既存番号を後から振り直して詰めないでください。

## 日常の操作

1. `GASG > Fighting Game > Open Animation Action Manager`を開きます。画面名は「モーション管理」です。
2. 登録済みモーションの表示名・Animation Clipを調整します。管理番号は読み取り専用です。
3. 新規登録ではキャラクター番号と分類を選び、「次の管理番号を提案」を押します。現在登録されている最大連番の次を提案します。
4. 表示名とClipを指定し、「新規モーションを追加」を押します。番号の形式違い・重複は拒否されます。新規Actionの内部接続IDは同じ管理番号を使います。
5. `Open Attack Motion Database`で技を選び、「再生モーション」を管理番号／表示名から割り当てます。入力コマンドを変える場合だけ「入力設定」を開きます。
6. 「検証（変更なし）」で番号を確認し、「Animatorへ反映・保存」で反映します。同期をスキップした場合はConsoleに理由が表示されます。

現在のカタログから削除済みの番号を永久予約する台帳機能はありません。運用では削除・番号再利用を避けてください。番号形式の検証は型を限定し、旧内部IDは移行互換のため引き続き許可しています。

## 技の名前とモーションの番号は分ける

- モーション：見た目の動作。管理番号・表示名・Clipを持ちます。
- 技データ：発生、持続、ダメージ、判定、キャンセルを持ち、モーションを参照します。
- 入力設定：どの操作でどの技を出すかを定めます。入力別の技IDは内部情報として保持します。

同じ昇龍拳を「623＋弱」と「必殺ボタン」の両方から出す場合も、モーション番号を増やす必要はありません。異なる技で同じClipを使っても、尺が異なる場合は別のモーション登録を使います。

今回の整理は管理番号と表示名が対象です。既存FBX／`.anim`ファイル名、骨名、技の数値、入力コマンド、Clip割り当ては保持しています。今後の新規書き出しファイルは管理番号に合わせて、例：`AS_p01_100_004.fbx`、抽出Clipは`AS_p01_100_004.anim`とすると照合しやすくなります。

命名整理の時点ではモーション割り当てを保持しました。その後の不具合修正で、立ち弱Pの参照を`AS_p01_100_001`へ修正済みです。昇龍拳のHitbox期間不一致と投げClip未設定は別の調整項目として残っています。

## バックアップ・検証

移行前のコードとDataは`ReviewBackups/Naming_20260907_101732/`へ保存済みです。変更した3つのDataアセットについて、管理番号・表示名・サブアセット名以外の差分がないことを確認しました。移行処理の再実行も変更なしでスキップします。

新規テストは番号形式、全角文字の拒否、重複検出、分類別の採番、表示名変更時の内部接続ID／Clip保持、既存17モーションの番号検証を対象にしています。

Unity 6000.3.11f1の複製プロジェクトでコンパイルし、既存テストを含む38件すべて成功しました。結果：`ReviewValidation/NamingResults.xml`、ログ：`ReviewValidation/NamingEditor.log`。描画を使わない検証で、URPシーンの見た目は対象外です。
