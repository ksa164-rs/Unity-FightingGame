# 対戦システムの振り返り（2026-09-07）

## 結論と確認範囲

現在は「データ駆動のローカル格闘プロトタイプ」です。基本の対戦確認には使えますが、SF6と同じ駆け引き・フレーム挙動を再現できる段階には達していません。ドライブ系の追加より先に、ガード、時間軸、接触の解決、調整画面と実データの一致を固める必要があります。

Unity 6000.3.11f1、URP 17.3.0、Input System 1.19.0、VFX Graph 17.3.0をプロジェクト設定から確認しました。Unity MCP接続は提供されていません。ソース、Data、Editor UI、設計文書を調査し、修正と回帰テストを追加しています。プレイヤーの操作感・アニメーションの見栄えの実機評価とは区別します。

SF6の最新パッチの数値を完全再現することは今回の前提にしていません。比較基準は対戦機能の構成です。SF6ではドライブゲージと5種の技術、バーンアウトが攻防の共通基盤です（[Capcom公式説明](https://news.capcomusa.com/2022/06/02/street-fighter-6-redefines-the-genre-in-2023/)）。個々の受付フレーム・補正率は対象バージョンを決めて別途検証する必要があります。

## 現状の良い土台

- キャラクターの対戦進行はMatchManagerの60Hz整数フレームに集約されています。
- 攻撃の発生・持続・後隙、ガード属性、硬直、HitboxはAttack Definitionから調整できます。
- Action IDとAnimation Clipが分離され、モーション名の変更で技IDが変わらない構成です。
- 技選択は方向コマンド、使用状態、入力ボタン、優先度を持つBinding方式へ移行しています。
- 判定表示、入力履歴、オプション、カメラ調整など、確認用の導線があります。

## 競合・不整合と今回の対応

| 優先 | 調査で確認した問題 | 影響 | 今回の対応 |
|---|---|---|---|
| 最優先 | FighterProjectileだけUpdate／deltaTimeで移動・寿命・命中を処理 | ヒットストップやオプション停止中にも弾が進む。対戦60Hzと異なる時間軸 | MatchManagerの60Hzへ統合。近接・弾の接触を検出してから適用。ラウンド終了・リセット時に登録弾を無効化 |
| 最優先 | CanBlockがNeutral/Crouchingしか許可しない | ガード硬直中の次の攻撃が通常ヒットになる | BlockStun中もそのフレームの後ろ入力と上下段条件でガード可能に修正 |
| 高 | 弾の命中で無条件にowner.attackConnectedをtrueにする | 弾を撃った後の別技がヒット確認キャンセルできてしまう | 発射時の攻撃実行IDを保持し、一致した攻撃だけヒット済みにする |
| 高 | Runtimeは7件のBinding、Editorは旧5枠から技を選択 | 波動拳など、追加した技を同じ調整画面で選べない | Bindingの表示名＋技IDから選択できるよう変更。Bindingが空の旧データのみ5枠を表示 |
| 中 | 空中横入力とガード押し戻し倍率、減速がコードの固定値 | デザイナーがInspectorだけで調整できない | FighterConfigの「空中操作・押し戻し」へ公開。初期値は従来と同じ |
| 中 | 発射0Fを設定できるが、生成確認はUpdateAttackの1F以降のみ | データの指定時刻と生成時刻が合わない | 攻撃開始時にも発射条件を確認 |
| 中 | SphereCastのみで弾判定 | 発射時から相手に重なる状況で検出が抜ける | 発射体の現在位置をOverlapSphereでも確認 |
| 中 | 弾の押し戻し方向に発射者の現在の向きを使用 | 発射後に位置が入れ替わると押す方向が変わる | 弾の飛翔方向を被攻撃側の押し戻しへ渡す |
| 高 | 同じAction IDへ別の尺／Clipを同期し、同じClipの別Stateも改名して転用する | 最後に処理された技の尺が残り、別技のStateを奪う | 尺／Clipの競合はController変更前に同期を中止。別Actionは同じClipでも別Stateとする。保存と同期のログも区別 |

既存の`AttackMotionDatabase_Prototype`を読み取り専用検証した結果、要確認は次の3件でした。数値・割り当ての意図を推測して既存アセットを変更していません。

1. **弱昇龍拳の集計値と実判定のズレ**：発生16／持続10／後隙23に対し、Hitboxは5〜14です。実判定は発生欄より11F早く出ます。Hitboxを16〜25へ動かすか発生欄を戻すかは、意図したモーションと実測を基準に決めてください。
2. **投げのClip未設定**：Knee BashのActionにAnimation Clipがありません。
3. **立ち弱Pと弱昇龍拳のAction共有**：同じAction参照（SpecialAttack）なのに、全体尺が14Fと49Fです。別Actionへ分けてからAnimator同期してください。新しい保護により、この矛盾が残っている間はAnimator同期をスキップします。データ編集・保存は可能です。

| 3 | 防御時の効果 | 通常ガードのヒットストップはなく、ガード削りは常に0。将来のバーンアウトやSAのルールを別属性で定義する必要がある | 技ごとのHit／Block効果＋共通状態ルール |

今回の検証ツールは、参照不足、技ID重複、同じ方向列・ボタン・優先度で使用状態が重なるBinding、同一Actionの尺／Clip競合、Hitboxと発生・持続の不一致、飛び道具の不正な発射設定、キャンセル範囲を報告します。異なる方向列が同時成立するケースや、全状態の到達可能性を証明するツールではありません。

## 実際に進める順序

1. **今回の修正をPlayで確認する。** 波動拳の停止、連続ガード、上下段切替、リセットを確認する。見た目のブラッシュアップより、結果が入力から再現できることを優先する。
2. **観測とフレーム規約を固める。** 1F送り、状態／技F／硬直残F、入力履歴、常時ガードを用意し、同じ操作列の結果を比較する。ここで外部フレーム表との換算を決める。
3. **接触・姿勢・距離を固める。** Hurtbox種別、しゃがみ形状、画面端Pushbox、同時接触規則、向きの固定条件を実装してから、歩行速度・技のリーチを調整する。
4. **技の攻防ルールを固める。** 投げ抜け／保護、ダウン／起き上がり、着地、無敵、カウンター、多段、コンボ補正の順に実装。各機能は条件と効果をデータ化して小さくテストする。
5. **ドライブとSAを加える。** 最初にゲージ消費・回復・バーンアウトを共通化し、OD、パリィ、インパクト、ラッシュ、リバーサル、SAを接続する。先に個別技へゲージ処理を埋め込まない。
6. **数値バランスと演出を詰める。** 発生・硬直差→リーチと押し戻し→ダメージ／補正→ゲージ収支→アニメーション／VFXの順で調整する。オンラインが必須なら、段階3より前に状態保存復元の設計も確定する。

## デザイナー／プランナーの操作

1. `GASG > Fighting Game > Open Attack Motion Database`を開く。
2. `編集する技`で表示名＋固定技IDを選ぶ。波動拳もここに表示される。同じAttackを参照する別入力の技は、攻撃値を共有する点に注意する。
3. 発生・持続・後隙とHitboxを調整したら、`このDatabaseの矛盾をチェック（変更なし）`を押す。Consoleの要確認メッセージに表示された技を修正する。
4. 共通の空中入力・ガード押し戻し・減速は `Assets/GASGFighter/Data/FighterConfig_Prototype.asset` の `空中操作・押し戻し` で調整する。空中入力倍率は現行移動処理の入力に掛かる値で、移動速度を比例変更する値ではない。
5. 全Databaseを調べる場合は `GASG > Fighting Game > Validate Combat Data (Read Only)` を使う。データは自動修正しない。

技IDは固定、表示名は自由、ClipはAction側、フレームと判定は攻撃側、キャラ共通値はConfig側という分担を維持します。新しい設定ファイルを増やす際は、既存設定と同じ値を重複して所有しないことを採用条件にします。
